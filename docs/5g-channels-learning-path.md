## 导言：先分清两个"信道"

这是整个学习过程中最容易混淆、也最需要一开始就理清的问题。5G 语境下"信道"一词指两件性质完全不同的事：

**物理信道**是协议造出来的东西。PDSCH、PDCCH、PRACH 这些名字指的是 3GPP 规范规定的一套信号结构——比特怎么编码、调制符号怎么映射到哪些时频资源、参考信号插在什么位置。它是人为设计的、写在标准文档里的、收发双方约定好的。你"生成"一个物理信道。

**传播信道**是客观存在的东西。无线电波从发射机到接收机，中间经历反射、衍射、散射，到达接收端时变成若干条不同时延、不同角度、不同衰减的路径的叠加。它是物理环境决定的、不以人的意志为转移的。你"经历"一个传播信道，只能去估计它，不能规定它。

两者的关系是一条完整的链：

```
   ┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
   │  信息比特    │ →  │  物理信道    │ →  │  传播信道    │ →  │  接收机      │
   │             │    │  (协议/编码/ │    │  (多径/衰落/ │    │  (估计/均衡/ │
   │             │    │   映射/波形) │    │   噪声)      │    │   解码)      │
   └─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘
                              ↑                                    ↑
                         38.211 / 38.212                     TR 38.901
                         TS 38.214 等                        TS 38.101/104
```

理解这条链的每一环、以及环与环之间的接口，就是全部学习内容。规范上，物理信道看 38.211/38.212/38.213/38.214，传播信道看 TR 38.901。

**关键认识**：物理信道的设计（尤其是参考信号的密度和位置）本质上是为了对付传播信道。DM-RS 之所以前置于时隙开头、之所以在频域上梳状分布，直接对应着信道的时变速度和频率选择性。不学传播信道，物理信道的设计决策就只能靠死记。

## 阶段一：地基——参数集、帧结构、资源网格

**目标**：在动手碰任何具体信道之前，先把"时频平面"这个舞台搭清楚。所有物理信道最终都是往一张资源网格上填东西，网格的坐标系必须先弄懂。

### 理论要补

NR 与 LTE 最大的结构性变化是取消了固定子载波间隔。NR 用参数集（numerology）μ 定义子载波间隔 Δf = 2^μ · 15 kHz：

| μ | Δf (kHz) | 每子帧时隙数 | 时隙长度 | 每时隙符号数（常规CP） | 典型用途 |
|---|---|---|---|---|---|
| 0 | 15 | 1 | 1 ms | 14 | FR1 广覆盖 |
| 1 | 30 | 2 | 0.5 ms | 14 | FR1 主力配置 |
| 2 | 60 | 4 | 0.25 ms | 14 | FR2 / 低时延 |
| 3 | 120 | 8 | 0.125 ms | 14 | FR2-1 毫米波 |
| 4 | 240 | 16 | 0.0625 ms | 14 | FR2-2 同步信号 |

要建立的因果链：μ 越大 → 符号越短 → 对多普勒扩展容忍度越高（因为符号时长 τ_sym 与信道相干时间 T_c 的比值变小）→ 适合高速移动和毫米波；但 μ 越大 → CP 绝对长度越短 → 对时延扩展的容忍度越低，覆盖越差。**这条权衡是 NR numerology 设计的核心，也是论文里写研究动机最有力的素材。**

配套概念：无线帧 10 ms、子帧 1 ms 固定；REG/RB（12 子载波）、RE（1 子载波 × 1 符号）的层级；BWP（带宽部分）如何把载波切块以适应不同终端带宽；TDD 下一个时隙内的符号可以是 D/U/F（下行/上行/灵活）三种类型。

### 工具箱怎么用

```matlab
carrier = nrCarrierConfig;
carrier.SubcarrierSpacing = 30;    % kHz
carrier.NSizeGrid = 52;            % 频域 RB 数
carrier.CyclicPrefix = 'normal';
carrier.NSlot = 0;
disp(carrier);                     % 关键：打印所有派生量
```

`disp(carrier)` 输出的采样率、每时隙样本数、时隙长度，逐个和 38.211 §4.3 的公式对上，这是第一周最有价值的练习。

### 验收

- 手算任意 μ 下 1 个时隙的样本数和绝对时长，用 `carrier` 对象验证
- 说清为什么 FR2 用 μ = 2/3，而 FR1 覆盖受限场景用 μ = 0
- 能画出并解释一张资源网格的示意图（横轴符号、纵轴子载波、标出 RB 边界）

## 阶段二：下行物理信道全覆盖

下行方向基站发、终端收。NR 下行有四个物理信道，另加若干参考信号。以下每个按「承载什么 → 处理链 → 资源映射 → 规范 → 函数 → 验收」展开。

### 2.1 SSB：同步信号块（PSS + SSS + PBCH）

**承载什么**：终端开机后第一件事就是找小区。SSB 提供时间/频率同步和最基本的小区信息。PSS 给粗同步和物理小区 ID 的一部分，SSS 给完整小区 ID，PBCH 承载 MIB（主信息块）。

**处理链**：MIB（24 比特）→ 加扰 → Polar 编码 → 速率匹配 → QPSK → 映射到 PBCH 的 240 个 RE（跨越 4 个符号）。PSS/SSS 是预定义的频域序列，不经编码。

**资源映射**：SSB 占 4 个 OFDM 符号 × 20 个 RB（240 子载波）。频域位置有候选集（由 `AbsoluteFrequencySSB` 和同步栅格决定）。μ = 0/1 时，SSB 在时隙的符号 2-5；μ = 3/4 时在符号 8-11。PSS 在第一个符号、SSS 在第三个、PBCH 在二三四。

**规范**：38.211 §7.4.3（SSB 结构），§7.4.2.2~7.4.2.3（PSS/SSS 序列），38.212 §7.1（PBCH 编码），38.213 §4.1（SSB 时域位置）。

**函数**：`nrSSB`、`nrSSBIndices`、`nrPBCH`、`nrPBCHIndices`、`nrPSS`、`nrSSS`。

**验收**：生成一个 SSB 并在时频平面上可视化；能说清为什么 PSS 用频域 Zadoff-Chu 序列（恒幅、低 PAPR、良好的相关特性）；能解释 SSB 的时域位置为什么随 μ 变化。

### 2.2 PDCCH：物理下行控制信道

**承载什么**：DCI（下行控制信息）。这是整个调度机制的神经中枢——终端必须先解出 PDCCH 才知道 PDSCH 占了哪些资源、用什么调制编码、HARQ 进程号是多少。没有 DCI，终端面对一堆 RE 完全不知道该解什么。

**处理链**：DCI 载荷 → CRC 附着（CRC 用 C-RNTI 等标识加掩）→ Polar 编码 → 速率匹配 → 加扰 → QPSK → 映射到 CCE。

**核心概念层次**：这是下行最复杂的一套机制，必须逐层理解。REG（资源元素组，1 符号 × 1 RB）→ CCE（控制信道单元，6 个 REG）→ 聚合等级（AL = 1/2/4/8/16，决定用几个 CCE）。终端不知道基站用哪个 AL、也不知道 DCI 在哪几个 CCE 上，所以要在**搜索空间**里盲检。搜索空间在 **CORESET**（控制资源集）定义的时频范围内。CORESET 给出"在哪片区域找"，搜索空间给出"具体试哪些位置和哪些聚合等级"。

**规范**：38.211 §7.3.2（PDCCH 映射），38.212 §7.3（Polar 与 DCI 格式），38.213 §10（搜索空间与盲检）。

**函数**：`nrPDCCH`、`nrPDCCHConfig`、`nrPDCCHIndices`、`nrPDCCHSpace`（生成搜索空间候选）、`nrCORESETConfig`、`nrSearchSpaceConfig`、`nrDCIEncode`、`nrDCIDecode`。

**验收**：能说清 CORESET 和搜索空间的分工；能生成一个 PDCCH 候选并用 `nrPDCCHSpace` 列出所有盲检位置。

### 2.3 PDSCH：物理下行共享信道

**承载什么**：下行用户数据。这是吞吐量的主要来源，也是仿真里用得最多的信道。

**处理链**：传输块 → CRC 附着 → LDPC 编码 → 速率匹配 → 加扰 → 调制 → 层映射 → 预编码 → RE 映射。

**必须掌握的三个环节**：

*TBS 计算*（38.214 §5.1.3.2）。先算中间量 N_info = N_RE · R · Q_m · ν，其中 N_RE 是可用资源元素数（已经扣掉 DM-RS 和开销）。再按码率量化，最后查表得 TBS。**这个公式的每一步都对应一个真实的设计权衡**：DM-RS 密度直接影响 N_RE，进而影响有效码率；所以"参考信号越密 → 信道估计越准但吞吐越低"这个权衡在 TBS 公式里是显式的。读 `nrTBS` 源码比看任何解释都清楚。

*LDPC 基图选择*。BG1 和 BG2 的切换由码率和 TBS 阈值决定。BG1 适合高码率大数据块，BG2 适合低码率小数据块。工具箱在 `nrDLSCH` 里自动处理。

*速率匹配*。把编码后的比特塞进实际可用 RE 数里，涉及比特选择、交织、冗余版本。HARQ 重传就是换一个冗余版本重发。

**规范**：38.211 §7.3.1（PDSCH 映射），38.212 §7.2（LDPC 链），38.214 §5.1（资源分配与 TBS）。

**函数**：`nrPDSCHConfig`、`nrPDSCH`、`nrPDSCHIndices`、`nrPDSCHDMRS`、`nrPDSCHPTRS`、`nrPDSCHDecode`、`nrDLSCH`、`nrDLSCHDecoder`、`nrTBS`。

**验收**：独立跑通"随机比特 → 波形"的完整下行链路；改 MCS、层数、PRB 数后说清 TBS 和有效码率怎么变。

### 2.4 CSI-RS：信道状态信息参考信号

**承载什么**：不承载信息，专门用于测量。基站发 CSI-RS，终端测量后反馈 CSI（包括 CQI、PMI、RI），基站据此做链路自适应和预编码选择。

**与 DM-RS 的分工**：这是 NR 相对 LTE 的一个重要设计分离。LTE 用 CRS 同时承担解调和测量两件事，导致 CRS 必须始终全带宽发送，开销大且无法针对特定终端优化。NR 拆开：DM-RS 只管解调（跟着数据走，只在有数据的资源上发），CSI-RS 只管测量（基站按需配置，可以稀疏、可以窄带、可以针对特定终端）。

**资源映射**：CSI-RS 的图样由 `CDMType`（码分复用类型）、`RowNumber`（图样行号，决定 RE 排布）、`Density`、`NumPorts` 等决定。配置灵活度很高，是 NR 里参数最复杂的信号之一。

**规范**：38.211 §7.4.1.5，38.214 §5.2（CSI 上报）。

**函数**：`nrCSIRS`、`nrCSIRSConfig`、`nrCSIRSIndices`。

**验收**：生成一个 CSI-RS 并在网格上标出位置；说清 CDM 类型如何影响可支持的端口数。

### 2.5 下行参考信号小结

NR 下行有三类参考信号，用途泾渭分明：

- **DM-RS**：解调用，跟着 PDSCH/PDCCH/PBCH 走。前置设计（front-loaded，第一个 DM-RS 在时隙开头）是为了让终端尽早开始信道估计，降低处理时延。频域梳状 + 时域附加符号的组合提供了对抗频率选择性和时变性的能力。
- **PT-RS**：相位跟踪用。毫米波频段相位噪声严重（本振不稳定导致公共相位误差），PT-RS 在时域上密集排布用于估计和补偿这个相位旋转。低频段通常不需要。
- **CSI-RS**：测量用，见上。

**验收**：能画一张表说清三类参考信号各自的密度、位置、用途和适用的频段场景。

## 阶段三：上行物理信道全覆盖

上行方向终端发、基站收。结构上与下行对称，但有几处本质差异，正是考点和论文题的集中地。

### 3.1 PRACH：物理随机接入信道

**承载什么**：终端请求接入网络的第一个信号。终端发前导（preamble），基站在整个小区搜前导，检测到就回随机接入响应。前导还隐含了终端的定时提前量估计依据。

**处理链**：选择前导序列（从 64 个前导中按逻辑根序列索引和循环移位生成）→ 映射到 PRACH 时机（occasion）→ 生成时域波形（PRACH 是唯一不经过标准 OFDM 调制的信道，它有自己独立的参数集）。

**关键概念**：根序列（Zadoff-Chu）、循环移位（不同移位之间正交，所以同一根序列能生成多个正交前导）、前导格式（format 0~3 对应不同的小区半径和覆盖需求，格式越长覆盖越远）、PRACH 时机配置（时频资源上的周期性机会）。

**规范**：38.211 §6.3.3（PRACH 序列生成），38.213 §8（随机接入过程）。

**函数**：`nrPRACH`、`nrPRACHConfig`、`nrPRACHIndices`。

**验收**：生成一个 PRACH 前导，画出它的自相关函数（能看到尖锐的峰值——这正是 Zadoff-Chu 用于同步的原因）；说清循环移位长度和小区半径如何权衡。

### 3.2 PUCCH：物理上行控制信道

**承载什么**：上行控制信息（UCI）——包括 HARQ-ACK（确认下行数据收到没有）、SR（调度请求，我要发数据了）、CSI（信道状态反馈）。

**五种格式**：PUCCH 格式 0 到 4，按"短/长"和"承载比特数"两个维度划分。格式 0 和 1 是短 PUCCH（占 1~2 个符号，可以在时隙末尾，用于低时延的快速反馈），格式 2、3、4 是长 PUCCH（占 4~14 个符号，承载更多比特）。格式 4 用正交扩频支持多用户复用。

**规范**：38.211 §6.3.2，38.213 §9。

**函数**：`nrPUCCH`、`nrPUCCH0`~`nrPUCCH4`、`nrPUCCHIndices`。

**验收**：说清短 PUCCH 和长 PUCCH 各自适合什么场景；能生成格式 0 和格式 1 的波形并对比。

### 3.3 PUSCH：物理上行共享信道

**承载什么**：上行用户数据。

**与 PDSCH 的三处关键差异**（这是本阶段最重要的内容）：

*变换预编码*。开启后 PUSCH 从 CP-OFDM 变成 DFT-s-OFDM，即在 IFFT 之前先做一次 DFT 扩频。效果是 PAPR 大幅降低（从约 10 dB 降到约 5~6 dB 量级），这对上行特别重要——终端功率受限、功放线性度差，低 PAPR 意味着同样的功放能输出更高功率，覆盖更好。代价是频域调度灵活性降低（必须占用连续的 RB）。**什么时候开：小区边缘、覆盖受限。什么时候不开：小区中心、追求调度灵活性和高吞吐。** 这个开关是 `nrPUSCHConfig` 的 `TransformPrecoding` 属性。

*DM-RS 类型与映射*。PUSCH 的 DM-RS 有 Type A 和 Type B 两种映射类型（对应 38.211 §6.4.1.1.3 的两张表），区别在于 DM-RS 相对 PUSCH 起始符号的位置规则。Type A 相对时隙边界定义，Type B 相对 PUSCH 分配的第一个符号定义。

*跳频*。上行支持时隙内跳频和时隙间跳频。作用是获得频率分集、随机化干扰。对覆盖边缘的终端，跳频能显著改善性能。

**规范**：38.211 §6.3.1（PUSCH 映射），38.212 §6.2（上行 LDPC 链），38.214 §6.1。

**函数**：`nrPUSCHConfig`、`nrPUSCH`、`nrPUSCHIndices`、`nrPUSCHDMRS`、`nrPUSCHPTRS`、`nrPUSCHDecode`、`nrULSCH`、`nrULSCHDecoder`。

**验收**：分别生成 CP-OFDM 和 DFT-s-OFDM 的上行波形，用互补累积分布函数（CCDF）比较两者的 PAPR 分布——**这张对比图是理解变换预编码价值的最直观方式，也是论文里常用的图**。

### 3.4 SRS：探测参考信号

**承载什么**：上行信道探测。基站通过 SRS 估计上行信道质量，用于上行调度、链路自适应、以及利用信道互易性推导下行预编码（TDD 模式下特别有价值）。

**关键概念**：SRS 资源集、跳频图样、梳状结构（comb，取值 2 或 4，决定 SRS 在频域上的疏密）、以及"基站如何用 SRS 估计到的上行信道去推下行信道"（依赖 TDD 互易性假设）。

**规范**：38.211 §6.4.1.4，38.214 §6.2。

**函数**：`nrSRS`、`nrSRSConfig`、`nrSRSIndices`。

**验收**：生成一个跳频 SRS 并画出它在多个符号上的频域位置；说清信道互易性的适用范围和失效条件。

### 3.5 上行参考信号小结

上行有 DM-RS、PT-RS、SRS 三类。与下行对比记忆：DM-RS 和 PT-RS 上下行都有（用途相同），CSI-RS 只在下行、SRS 只在上行（方向不同的测量需求）。

**验收**：能画一张上下行参考信号对照表，标出各自的规范章节和工具箱函数。

## 阶段四：传播信道（上）——大尺度模型

从这一阶段起进入传播信道。大尺度模型描述"平均意义上信号衰减了多少"，是链路预算和覆盖分析的基础。

### 4.1 自由空间路损

Friis 公式，路损随距离平方衰减、随频率平方增长。作为理论基准，实际场景用它做参照。注意低频段的路径损耗指数接近 2，城区非视距可达 3.5~5。

### 4.2 3GPP 场景化路损模型

TR 38.901 定义了四类场景，每类又分 LOS 和 NLOS 两种情况：

- **UMa**（Urban Macro）：宏基站，站高 25 m，覆盖大
- **UMi**（Urban Micro）：微基站，站高 10 m，街道峡谷
- **RMa**（Rural Macro）：农村宏站，站高 35 m
- **InH**（Indoor Hotspot）：室内热点

每个场景的 LOS 概率是距离的分段函数，路损公式也是分段的——近距离用自由空间类公式，超过断点距离 d_BP 后斜率变陡。**断点距离 d_BP 的存在是"两条射线（直射 + 地面反射）干涉"的物理结果**，理解这一点才能理解为什么公式是分段的。

**规范**：TR 38.901 §7.4。

**函数**：`nrPathLossConfig`、`nrPathLoss`。

**验收**：画出 UMa 场景下 LOS 和 NLOS 的路损随距离变化曲线；说清断点距离的物理来源。

### 4.3 阴影衰落

路损公式给的是平均损耗，实际接收功率在其周围对数正态分布波动，这就是阴影衰落（也叫慢衰落），标准差 σ 通常 4~8 dB。

**关键点**：阴影衰落的标准差和距离相关性（相邻位置的阴影衰落是相关的，不是独立的）会显著影响覆盖率和中断概率。

### 4.4 小结与验收

能独立完成一个链路预算：给定发射功率、天线增益、距离、场景和阴影衰落裕量，算出接收功率和信噪比，判断能否解调。

## 阶段五：传播信道（下）——小尺度模型

这是传播信道的核心，也是整个学习过程中数学密度最高的部分。详细的公式推导见配套文件 `channel-theory-notes.md`，这里给出学习脉络。

### 5.1 时变多径信道模型

从最一般的时变冲激响应 h(τ, t) 出发。τ 是时延变量、t 是绝对时间变量，两者地位完全不同——h(τ, t) 表示"在时刻 t 观察到的、由时刻 t−τ 发出的脉冲所产生的响应"。

在 WSSUS（广义平稳非相关散射）假设下，这个二维函数可以被解耦成两个一维的描述：

- **时延维度** → 功率延迟谱（PDP），其傅里叶变换给出**频率自相关**，特征是**相干带宽**
- **时间维度** → 多普勒谱，其傅里叶变换给出**时间自相关**，特征是**相干时间**

**理解 WSSUS 的两个假设**：广义平稳指信道统计特性不随时间漂移（短时间内成立）；非相关散射指不同时延的路径互不相关（通常成立）。WSSUS 是绝大多数信道模型的基础假设，也是通信理论里最有效的简化之一。

**规范**：TR 38.901 §7.5。

### 5.2 TDL 模型

抽头延迟线模型。用 L 个抽头模拟多径，每个抽头有固定的时延 τ_l 和时变的复幅度 a_l(t)：

```
y(t) = Σ_l a_l(t) · x(t − τ_l)
```

幅度服从 Rayleigh（NLOS）或 Rician（LOS）分布。3GPP 规定了 TDL-A/B/C（NLOS）和 TDL-D/E（LOS）五组标准抽头，每组的时延和平均功率是定值，直接查表。

**工具箱**：`nrTDLChannel`。

**什么时候用 TDL**：需要快速验证算法、不需要空间维度、或者做理论分析时。计算量小，参数直观。

### 5.3 CDL 模型

分簇延迟线模型。在 TDL 基础上增加了**角度维度**——每个簇不仅有延迟和功率，还有离开角（AoD/ZoD）和到达角（AoA/ZoA）。多个天线阵元之间因此产生相位差，这就产生了**空间相关性**，是 MIMO 和波束赋形仿真必需的。

3GPP 规定了 CDL-A/B/C（NLOS）和 CDL-D/E（LOS）五组标准模型。

**工具箱**：`nrCDLChannel`。

**什么时候用 CDL**：多天线、波束赋形、大规模 MIMO、空间复用等任何需要空间维度的仿真。计算量大很多。

**验收**：能画出所配置信道的功率延迟谱和频率响应；能解释延迟扩展如何决定相干带宽、多普勒如何决定相干时间；**能说清这条因果链如何反过来决定了子载波间隔和 DM-RS 密度的设计**——这是把物理信道和传播信道真正连起来的关键，也是论文里最有说服力的分析。

### 5.4 空间维度与相关矩阵

多天线情形下信道从标量变成矩阵 H（N_r × N_t）。阵列响应向量描述阵元间的相位差，与阵型（ULA/UPA）和角度有关。空间相关矩阵（发射端和接收端各一个）刻画天线间的相关性，Kronecker 模型把两者分离处理。相关性与 MIMO 容量直接相关——高相关时空间复用增益下降。

**验收**：能画出不同角度扩展下的空间相关矩阵热力图；说清相关性和 MIMO 容量的关系。

## 阶段六：信道估计与均衡

传播信道是未知的，接收机必须先把它估计出来才能恢复数据。这一阶段是把前面所有内容武器化的地方。

### 6.1 估计的基本框架

在导频位置，接收信号是 Y_p = H_p X_p + W_p。已知 X_p（导频符号是收发双方约定的），因此可以反解 H_p。问题在于如何从导频位置的估计值得到整个时频平面的信道（导频是稀疏的，数据 RE 上没有导频）。

三步：**导频处估计 → 插值到全网格 → 跟踪时变**。

### 6.2 LS 与 MMSE 估计器

**LS（最小二乘）**：直接除以发送的导频符号。实现简单，但噪声被放大——估计误差正比于 1/|X_p|²，导频功率低时误差大。

**MMSE（最小均方误差）**：利用信道的统计先验（相关矩阵 R_HH）来抑制噪声。估计误差比 LS 小，代价是需要知道 R_HH（从功率延迟谱和多普勒谱得到）和噪声方差。详细推导见理论笔记。

**工具箱**：`nrChannelEstimate`（支持 LS 和 MMSE，以及不同的插值方式）。

### 6.3 均衡器

信道在频域上是有起伏的，某些子载波深衰落，均衡就是补偿这个起伏。

**ZF（迫零）**：直接用估计信道的倒数。完全消除符号间干扰，但在深衰落子载波上噪声被剧烈放大。

**MMSE（最小均方误差）**：在消除干扰和抑制噪声之间取平衡。代价是需要噪声方差估计。

**工具箱**：`nrEqualizeMMSE`。ZF 可以用逐元素除法手写。

### 6.4 验收

- 能写出 LS 和 MMSE 估计器的公式（见理论笔记）
- 能画出估计误差随信噪比变化的曲线，对比 LS 和 MMSE
- 能说清深衰落子载波上 ZF 和 MMSE 的性能差异及其原因

## 阶段七：端到端打通

前面六个阶段各自独立，这一阶段把它们串成完整链路。

```
随机比特 → TBS计算 → CRC → LDPC编码 → 速率匹配 → 加扰 → 调制
    → 层映射 → 预编码 → RE映射 → DM-RS插入 → OFDM调制
    → [传播信道: CDL/TDL + 噪声]
    → OFDM解调 → 信道估计(利用DM-RS) → 均衡 → 解层映射
    → 解调 → 解扰 → 解速率匹配 → LDPC解码 → CRC校验 → 误块率统计
```

**官方最佳起点**：`NR PDSCH Throughput` 示例。它把上面整条链都实现了，先跑通、再逐行读懂、然后改参数做实验。吃透这一个，比看十个教程有用。

### 性能评估方法论

科研仿真和"跑通例子"的分界线在于能不能给出可发表的结果并解释它。

- **BLER-SNR 曲线**：横轴信噪比（dB），纵轴误块率（log 尺度）。**样本量是最大的坑**：BLER 低于 1e-3 时每点至少几千个传输块，否则曲线抖动会掩盖真实的性能差异，得出错误结论。
- **吞吐量曲线**：体现链路自适应的实际效果，注意峰值受码率上限和调度策略限制。
- **信道实现数**：CDL/TDL 是随机信道，每个信噪比点要在多个信道实现上平均，否则结果不具统计意义。
- **可复现性**：固定 `rng` 种子，记录全部参数，序列化保存配置对象。**结果无法复现是审稿意见里最常见的批评之一。**
- **链路到系统映射**（L2S）：链路级给出 BLER 曲线，系统级需要有效信噪比映射（EESM 或 MI-ESM）。若课题涉及系统级，需要额外学这块。

### 验收

能独立完成一个完整的链路级仿真，产出 BLER-SNR 曲线和吞吐量曲线，并用阶段五的信道理论解释曲线在不同信道配置下的形状差异。

## 附录 D：学习方法要点

**读源码是最高效的路径**。5G Toolbox 大量函数是开放的 `.m` 文件，`edit nrTBS`、`edit nrPDSCHIndices`、`edit nrChannelEstimate` 直接能看到实现。规范条文抽象，对着实现看立刻明白。这也是工具箱相比"从零自己写"的最大价值——它是一份正确的参考实现。

**从示例出发而不是从函数列表出发**。工具箱有几百个函数，按文档目录线性学完不现实。更好的路径：找一个接近课题的官方示例 → 跑通 → 逐行读懂 → 改参数实验 → 替换模块做自己的研究。

**物理信道和传播信道要交叉学**。单独学物理信道会变成死记参数，单独学传播信道会脱离实际系统。每学一个物理信道，就问一句"它的参考信号设计在对付传播信道的什么特性"；每学一个传播信道特性，就问一句"它迫使物理信道做了什么设计妥协"。

**建立对照笔记**。每学一个模块记三样：规范位置、工具箱函数、可运行的验证例子。三样对上了才算真懂。

**注意版本陷阱**。R2021a 前后 API 差异大，网上教程大量是旧的。函数报错先查 `ver('nr')` 和本机 `doc`。
